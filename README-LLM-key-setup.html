Set up AI for your research

Connect an AI provider to suggest Q&A tags, codes, and related excerpts. Use your own API key, or run a model on your computer with Ollama.

New to ChromaScribe? Install the app first, then return here. ChromaScribe itself needs no account or Firebase setup.

1

Choose your AI provider

For hosted AI, create a key with your provider and choose a text chat model available to your account. Keep the exact model ID handy; you’ll need it in step 2.

Before using participant data

A hosted provider receives the transcript content sent for AI processing. Check its data policy and your study’s requirements first. A downloaded model running through local Ollama processes that content on your computer.

Google AI Studio

Create an API key in AI Studio, then choose an available Gemini text chat model. We use Google for the example below.

Groq

Create a Groq key for your own account. The Groq settings below use openai/gpt-oss-20b, which supports structured responses for code generation. Check that your account can use this model.

Create an OpenRouter key and choose a text chat model. Copy the full model ID, including the organization prefix.

OpenAI

Create an API key and choose a model that supports Chat Completions. Check your account’s model access and API billing.

Ollama on your computer — no API key

Install and start Ollama, then download the model used in ChromaScribe’s template:

Terminal or PowerShell 
ollama pull qwen3:latest

Keep Ollama running while you use AI features. Model size and speed depend on your computer. See available model sizes.

Use ollama list to see downloaded models. The Ollama API guide explains its local endpoint.

Model names, access, and usage limits can change. Choose a text chat model, rather than one intended only for audio, images, or embeddings.

2

Save your settings in .env

.env is a settings file in your ChromaScribe folder, next to app.py. Open a terminal in that folder. If the file already exists, keep it and edit it.

These commands create the file only if it is missing.

macOS / Linux terminal 
if [ ! -f .env ]; then
    cp .env.template .env
fi
Windows PowerShell 
if (-not (Test-Path .env)) {
    Copy-Item .env.template .env
}

Open .env in a text editor. Replace the three existing LLM_* lines with your provider’s settings; don’t add a second copy of them.

LLM_BASE_URL
Your provider’s API address, listed in step 1.
LLM_MODEL
The exact model ID from that provider.
LLM_API_KEY
Your own key. Leave it empty for local Ollama.

Example: Google AI Studio

Replace both highlighted placeholders. For another hosted provider, also replace the API address.

Edit these lines in .env 
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
LLM_MODEL=your_available_gemini_model_id
LLM_API_KEY=your_own_api_key
Example: Groq

Replace the three AI settings with these lines, then replace the key placeholder with your own Groq key.

.env for Groq 
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=openai/gpt-oss-20b
LLM_API_KEY=your_own_groq_key

ChromaScribe asks this model for a structured code response. See Groq’s structured-output guide. The app detects Groq from the API address above; LLM_PROVIDER is not needed. Remove an old override to keep your settings clear. If you use a custom proxy that forwards to Groq, set LLM_PROVIDER=groq.

For code generation with Groq’s GPT-OSS 20B or 120B, ChromaScribe sets a default output allowance of 16,384 tokens. To change it, set LLM_MAX_TOKENS to a positive whole number within your model’s limit in .env, then restart the app.

Using local Ollama instead?

Keep the template’s settings below. No API key is needed for the downloaded local model.

.env for local Ollama 
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen3:latest
LLM_API_KEY=
Keep your key private

Save it only in your local .env, which Git ignores. Leave it out of screenshots, messages, and commits. If a key has been shared, revoke it with your provider and create a replacement.

Use the base URL without /models or /chat/completions at the end. Leave the other settings unchanged. On a Mac, press Cmd+Shift+. in Finder to show hidden files, or run open -e .env.

3

Start the app and try a small project

If the app is running, stop it with Ctrl+C. With your Python environment active, start it again from this repository’s folder so it reads the saved settings:

From your ChromaScribe folder 
python app.py
PowerShell won’t activate the Python environment?

You can run the environment’s Python directly, without changing PowerShell’s execution policy:

Windows PowerShell 
.\.venv\Scripts\python.exe app.py
  1. Open ChromaScribe and create a new project.
  2. Upload a short fictional transcript and a few interview questions.
  3. Run AI processing, then review the Q&A tags, codes, and linked excerpts.

A demo already has results, so opening it doesn’t test your API key. Watch the terminal for connection errors. Manual editing and saved projects remain available even if AI processing is unavailable.

Open ChromaScribe

This edition uses one local workspace, saved in .private/runtime by default. It has no sign-in or automatic device sync. Keep it at 127.0.0.1, rather than exposing it on a public URL.

Something isn’t working?

Open the message that matches what you see. Keep keys and participant details out of anything you share for help.

Connection refused

Keep python app.py running. For local AI, start Ollama too. For hosted AI, check the provider’s API address and your network access.

401 or 403: key or access problem

Check that the key belongs to the provider in LLM_BASE_URL and that your account can use the model. Save .env and restart the app. If the settings still look wrong, check terminal overrides below.

404: model not found

Check the exact model ID and base URL. For Ollama, run ollama list and download the model if it is missing. A 404 from the optional /models check may simply mean that endpoint is unsupported.

429 or 503: usage limit or service unavailable

For 429, check your provider’s usage and billing page. A temporary rate limit may clear after a wait; exhausted quota may need an account change. For 503, check the provider’s status page and try again later.

Groq could not finish a valid code response

Groq rejected the generated JSON. Try again; if it keeps happening, increase LLM_MAX_TOKENS within your model’s limit or use a smaller transcript. Restart the app after changing .env.

No codes generated, or output could not be read

Q&A tagging and code generation use separate requests. Tagging can fall back to local matching when an AI request fails, so Q&A tags alone do not confirm that the provider returned usable codes.

“Could not be read as codes” means the reply did not contain usable code data. For Groq, check the model settings above and restart the app after updating it. Try a short fictional sample and check the code-generation error.

The AI reply was cut off

The reply reached its output-token limit. You can override the code-generation output allowance with LLM_MAX_TOKENS in .env, using a larger positive integer within your model’s limit, or use a smaller transcript. Restart the app after changing the setting. A larger allowance may use more tokens.

A sign-in page appears

You may be running another edition or checkout. Start this repository’s app.py and check whether another server is using port 5001.

My saved settings aren’t taking effect

First, save .env and restart ChromaScribe from the same project folder. Use one active value for each setting.

Variables already set in your terminal take priority over .env. This check prints their names, without showing their values:

Python environment active 
python -c "
import os

setting_names = ('LLM_BASE_URL', 'LLM_MODEL', 'LLM_API_KEY', 'LLM_PROVIDER')
for setting_name in setting_names:
    if setting_name in os.environ:
        print(setting_name + ' is set in this terminal')
"

To use .env instead, clear those overrides in this terminal, then restart the app:

macOS / Linux terminal 
unset LLM_BASE_URL LLM_MODEL LLM_API_KEY LLM_PROVIDER
Windows PowerShell 
Remove-Item Env:LLM_BASE_URL, Env:LLM_MODEL, Env:LLM_API_KEY, Env:LLM_PROVIDER -ErrorAction SilentlyContinue

If overrides return in a new terminal, update where you originally set them, such as your shell profile or operating system settings.

Optional: list the models your endpoint returns

Run this in another terminal, from the project folder with the same Python environment active. It reads your configuration without printing the key.

Terminal or PowerShell 
python -c "
from dotenv import load_dotenv
from openai import OpenAI
from processing_scripts.llm_config import resolve_llm_config

load_dotenv('.env')
provider, base_url, model, api_key = resolve_llm_config()
client = OpenAI(base_url=base_url, api_key=api_key)
for available_model in client.models.list():
    print(available_model.id)
"

Some providers don’t offer a model-list endpoint; others list models without checking a key. Use a new sample project to test the complete workflow.
