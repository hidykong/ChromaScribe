ChromaScribe local edition

Set up your AI model

Use a model on your computer or connect your own hosted AI key. ChromaScribe opens without an account. These settings are only for AI suggestions; Firebase setup is not needed.

LLM_BASE_URL

The provider's API address.

LLM_MODEL

The exact text chat model ID.

LLM_API_KEY

Your provider's key; empty for local Ollama.

Switch systems to see the matching commands.

Commands are labeled for Windows PowerShell or the macOS / Linux Terminal.

1

Pick a provider

The template uses local Ollama. Install and start Ollama, then download a model:

Terminal or PowerShell
ollama pull qwen3:latest

Keep Ollama running while using AI features. A downloaded local model runs on your computer, and its speed depends on your hardware. See Ollama's compatibility documentation.

For hosted AI, use a provider's OpenAI-compatible chat API. These are two options:

ProviderAPI base URLInstructions
Google AI Studiohttps://generativelanguage.googleapis.com/v1beta/openaiProvider documentation
Groqhttps://api.groq.com/openai/v1Provider documentation
Using interview data with hosted AI

Hosted AI requests send transcript content to the provider. Review its data policy, costs, and your study's requirements before using participant data. Start with a small sample to check the model's output.

2

Get an API key

Skip this step for a downloaded local Ollama model. For hosted AI:

  1. Sign in to your provider's console. Open Google AI Studio's API keys page or Groq's API keys page.
  2. Create a key for your own account and copy it when the provider displays it.
  3. Save it in your local .env file in step 4.

A key works only with its provider and the models your account can access. Keep it out of screenshots, messages, and Git commits.

3

Choose a model

Choose a text chat model. Copy its exact ID from the provider's current model list. Speech, image, and embedding models do not perform the tagging and code-generation tasks.

For Ollama, ollama list shows downloaded models. The template uses qwen3:latest.

If your hosted provider supports listing models through its API, replace both placeholders below. Use curl on macOS / Linux and curl.exe in Windows PowerShell:

Windows · PowerShell
curl.exe "YOUR_BASE_URL/models" -H "Authorization: Bearer YOUR_KEY"
macOS / Linux · Terminal
curl "YOUR_BASE_URL/models" -H "Authorization: Bearer YOUR_KEY"

Some providers do not expose this endpoint; use their console or documentation instead. A successful model list confirms access, but you still need to try generation with the selected model.

4

Create your .env file

From the project folder, copy the template once. If .env already exists, edit it instead of overwriting it.

Windows · PowerShell
Copy-Item .env.template .env
macOS / Linux · Terminal
cp .env.template .env

On macOS, Finder hides dotfiles. Press Cmd+Shift+. to show them, or use open -e .env to edit the file.

Local Ollama

Keep the template's three AI settings:

.env
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen3:latest
LLM_API_KEY=

Your own hosted key

Replace those same three lines with your provider settings. For example, Google AI Studio:

.env
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
LLM_MODEL=your_available_gemini_model_id
LLM_API_KEY=your_own_api_key
  • Replace the model and key placeholders. Keep only one active value for each variable.
  • Use the API base URL without /models or /chat/completions at the end.
  • Keep .env private. Git ignores it; only the credential-free template is tracked.
  • No Firebase settings or account credentials are used in this edition.
5

Restart and verify

With your Python environment active, start ChromaScribe:

Terminal or PowerShell
python app.py

Open http://127.0.0.1:5001. The project page opens directly. Create a small test project, upload transcripts and questions, and run the AI processing. Review its tags and codes.

Watch the terminal for the configured provider, model, and any errors. Source checks do not verify your live AI key. A demo or saved project may already contain results, so it is not enough to confirm the provider connection.

If the app is already running, stop it with Ctrl+C and start it again after editing .env. Saved project files remain on disk.

Troubleshooting

ProblemWhat to check
Connection refused by OllamaStart Ollama and confirm the base URL is http://localhost:11434/v1. The application and Ollama are separate processes.
401 or 403 from hosted AICheck that the key belongs to this provider and has access. Create a replacement if the key was revoked or exposed.
Model not foundChoose an exact model ID available to your account. For Ollama, download the model with ollama pull.
429 or quota errorCheck your provider's usage limits. Retry when the limit clears or use another available model.
Empty or unreadable outputTry a smaller sample and another text chat model. API compatibility does not guarantee useful tags or correctly formatted codes.
Settings do not changeRestart the app. Environment variables already set in your terminal override values in .env.
Sign-in page appearsStart this local edition's checkout and check whether a different server is using the same port.

When reporting a problem, include the provider, model ID, and error text. Remove keys, participant names, and transcript content from anything you share.
