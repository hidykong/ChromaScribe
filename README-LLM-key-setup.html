ChromaScribe local edition

Setting up your LLM API key

ChromaScribe uses a large language model to tag interview questions and answers, generate themes, and find similar excerpts. You can use a hosted provider with an OpenAI-compatible chat API, or run a downloaded model locally with Ollama. You configure it with three settings. The purple boxes show one worked example using Groq.

This edition opens without a ChromaScribe account or Firebase setup. These settings are for AI features. Start with the installation steps in the ChromaScribe README, then follow this guide from your project folder with the Python environment active.

LLM_BASE_URL

The provider's API address.

LLM_MODEL

The model ID, from the provider's model list.

LLM_API_KEY

Your provider's secret key; empty for local Ollama.

Commands below are shown for your system. Switch any time.

Each command is shown twice: once for Windows PowerShell and once for the macOS or Linux Terminal.

1

If you choose local Ollama

Install and start Ollama, then download the template's model. You can skip Ollama entirely when using a hosted provider.

Terminal or PowerShell
ollama pull qwen3:latest

Leave Ollama running while using AI features. Model size and speed depend on your computer. See the Qwen3 model page for available sizes.

Where your data goes

Hosted AI requests send transcript content to your chosen provider. Check its data policy and any requirements for your research data before using real participant material. Inference with a downloaded local Ollama model runs on your computer; choosing a cloud model sends requests to its provider.

2

Get an API key

Sign in to your provider's console, open its API keys page, and create your own key. Copy the full key when it is shown. This is an account with the AI provider; ChromaScribe itself has no sign-in step. Skip this section for a downloaded local Ollama model.

Example: Groq
  1. Sign in at Groq's API keys page.
  2. Create an API key and give it a name you will recognize, such as ChromaScribe local.
  3. Copy the full key into your local .env file in step 4.

Groq's quick start has the current setup instructions.

Keep the key private

Store it only in your local .env, which Git ignores. Do not paste it into this HTML file, source code, screenshots, messages, or Git commits. If a real key has been shared, revoke it in the provider's console and create a replacement.

3

Choose a model

Pick a general-purpose text chat model that supports the provider's Chat Completions API. Copy its ID exactly as listed. Check its context and output limits against your transcript size. Skip models intended only for speech, images, embeddings, or safety classification.

Use the provider's model list or console to find a model available to your account. Some providers also offer a /models endpoint; the optional check in step 5 reads your key from .env so you do not need to paste it into a terminal command.

Example: Groq

Groq currently lists openai/gpt-oss-20b among its supported models. It is used in the configuration example below. Confirm your account can access it, then review the generated tags and codes on a small test project.

For local Ollama, run ollama list to see downloaded models. The template uses qwen3:latest; the download command in step 1 installs it.

4

Create your .env file

ChromaScribe reads settings from a .env file in the project root. On your first run, copy .env.template using the command for your system. If .env already exists, keep it and edit the existing settings below.

Windows · PowerShell, project root
Copy-Item .env.template .env
macOS / Linux · Terminal, project root
cp .env.template .env

On macOS, Finder hides files that start with a dot. Press Cmd+Shift+. to show them, or open the file with open -e .env (TextEdit). On any system, you can open it in your code editor.

Choose one set of AI settings

The template already has three active LLM_* lines for local Ollama. Keep them for local inference, or replace all three with your hosted provider's values:

.env · local Ollama default
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen3:latest
LLM_API_KEY=
Example: Groq

Replace the three Ollama lines with these. Replace the highlighted key placeholder with your own key:

.env · hosted Groq
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=openai/gpt-oss-20b
LLM_API_KEY=your_own_api_key

Rules that prevent most errors

  • Use the exact variable names shown above and one active value for each. Replace the template's lines instead of appending duplicates.
  • Use the provider's API base URL, without /models or /chat/completions at the end.
  • Use a model ID available from that same provider. A model name from a different service may not work.
  • For a downloaded local Ollama model, leave LLM_API_KEY= empty.
  • Never commit .env. Only the credential-free .env.template belongs in Git.
No Firebase settings or service-account JSON are used in this edition. Leave the other local settings as described in the README. The default project data folder is .private/runtime, on the computer running ChromaScribe.
5

Restart and verify

If ChromaScribe is running, stop it with Ctrl+C (also Control+C on a Mac). Start it again after editing .env, with your Python environment active:

Terminal or PowerShell · project root
python app.py

Open http://127.0.0.1:5001. The project page opens directly. Create a small test project, upload sample transcripts and questions, and run AI processing. Review the generated Q&A tags and codes.

Watch the terminal for the configured provider, model, and any errors. A demo or saved project may already contain results, so opening one does not confirm the new AI connection. Manual editing and saved projects remain available without a working AI service.

Optional: list models through your configured endpoint

In another terminal, activate the same Python environment and run this from the project folder. It reads your existing configuration and prints model IDs, without printing your key:

Terminal or PowerShell · project root, Python environment active
python -c "
from dotenv import load_dotenv
from openai import OpenAI
from processing_scripts.llm_config import resolve_llm_config

load_dotenv('.env')
provider, base_url, model, api_key = resolve_llm_config()
client = OpenAI(base_url=base_url, api_key=api_key)
for available_model in client.models.list():
    print(available_model.id)
"

A model list confirms that endpoint responded; it does not prove a model accepts ChromaScribe's requests or produces useful output. Some providers do not expose this endpoint, and some list models publicly without checking a key. Use the small project test above to check the full workflow.

This is one local workspace, with files saved on the application computer and no automatic device sync. Keep the app at 127.0.0.1; this edition has no user access controls.

Troubleshooting

Find the problem or terminal message in the left column.

ProblemWhat it meansWhat to check
Connection refused The app or AI service is not reachable. Keep python app.py running. For local AI, also start Ollama. For hosted AI, check the provider's base URL and network access.
401 / 403
Key or access error		 The provider rejected the key or denied access. Check the key belongs to this provider and has access. An existing shell variable may override .env; see below. Replace revoked or exposed keys.
404
model_not_found		 The model is unavailable, or the API address is wrong. Check the base URL and exact model ID. For Ollama, run ollama list and download the model if needed. A 404 from /models alone may mean that endpoint is unsupported.
429
Rate limit or quota		 Your account has hit a request, usage, or billing limit. Check the provider's usage page. Retry after a temporary limit clears; a depleted quota may need an account change.
503
Service unavailable		 The provider is temporarily unavailable. Check its status page and retry later.
Empty content or no themes parsed The model returned empty output or a format the app could not read. Try a smaller sample and another text chat model. Check the model's request and output limits. API compatibility alone does not guarantee usable tags or codes.
Settings do not change The running app has old settings, or shell variables override .env. Use one active value for each LLM_* variable, check the project folder, and restart the app.
A sign-in page appears A different checkout or server is running. Start this local edition's checkout and check whether another server is using the same port.

Check for shell overrides

Environment variables already set in your terminal take priority over .env. This command prints only variable names, without showing any values:

Terminal or PowerShell · Python environment active
python -c "
import os

setting_names = ('LLM_BASE_URL', 'LLM_MODEL', 'LLM_API_KEY')
for setting_name in setting_names:
    if setting_name in os.environ:
        print(setting_name + ' is set in this terminal')
"

If you want the values in .env to take effect, clear those overrides in this terminal, then restart ChromaScribe from it. If they return in new terminals, update the place where you originally set them, such as your shell profile or operating system's environment settings.

Windows · PowerShell
Remove-Item Env:LLM_BASE_URL, Env:LLM_MODEL, Env:LLM_API_KEY -ErrorAction SilentlyContinue
macOS / Linux · Terminal
unset LLM_BASE_URL LLM_MODEL LLM_API_KEY

When reporting a problem, include the provider, model ID, and error message. Remove keys, participant names, and transcript content from anything you share.
